## Description
Owner 2026-10-19: Ollama now serves cloud models directly (docs.ollama.com/cloud: https://ollama.com/api/chat + /v1, Authorization: Bearer $OLLAMA_API_KEY, bare names from /api/tags such as gemma4:31b). Support it so the council does not depend on a local Ollama. Already in place (2026-10-19): ollama.com /api/show is public and declares the trained context (gemma4:31b 262144 BF16 = local gemma4:31b-cloud; glm-5.3-flash 1048576; minimax-m3 512000; kimi-k2.6 262144); ollama.com recommendations cover gemma4:31b-cloud (stem match); provider_caps.is_cloud_service() marks the host cloud; the /v1 path reads /api/show when /props has no window; failed /api/show no longer cached. Gaps found: endpoint key only as api_key in TOML (needs key_file / OLLAMA_API_KEY, never the secret in config); ollama_upstream has no notion of a keyed cloud default; ollama_slots plan lookup goes through a local /api/me or ~/.ollama signing (needs Bearer /api/me or a configured plan); connection-slot accounting must count direct cloud calls with the same account; think levels from recommendations on the direct wire; name translation between local '-cloud' tags and bare cloud names.
