## Description
Found in the ch-15 cloud run (csl-2026-10-25-0931-a7d3, researcher deepseek-v4.1-flash pinned num_ctx 32768). The researcher's head was 18,416 prompt tokens before any research: 7,003 + 2,454 chars of system turns plus a 50,185-char PROJECT ANCHOR FILES block (this repo's CLAUDE.md, 27k of it the status banner). Council grounding comes from build_grounding_messages() (claude_hooks/caliber_proxy/prompt.py) with the caliber proxy's fixed CALIBER_GROUNDING_ANCHOR_MAX_BYTES = 50,000, independent of the window (consultants/server/runner.py:196 and :766). Compaction keeps the head, so every fold landed at ~23-24k tokens and the next read_file (≤ 50k chars) pushed it past 32k again: prompts up to ~37k on a 32,768 window ("leaves -8692"), "no cut makes progress" x5, writer cut by its cap x3, 145 researcher:compaction calls (1.00M prompt / 301k completion) for 67 research calls. ollama.com ignored the pin; a real 32k server would have refused those calls. Proposal (owner's call, changes every council's prompt): cap the anchor block at a share of the smallest enabled role window (e.g. 10% of the window in tokens at the measured chars/token), so windows ≥ 256k stay byte-identical (cap ≥ 50 KB) and a 32k role gets ~12 KB; a cut anchor names the files left out and says read_file reaches them.
