## Description
Owner request 2026-10-24.

1. A held claim's expiry can be extended in place (e.g. `claude-hooks-res extend <claim|res> --ttl 2h` plus a `resource-extend` MCP tool on both memory servers). Today `renew` refreshes only the lease, so a holder who needs more time must release and re-acquire, which loses its place in the queue (seen 2026-10-23 in backup_models).
2. Waiters are told when the claim they wait behind is extended. A background `wait` should wake the session that set it with the new expected free time, through NOTIFY plus a short event line, and not exit as though it had been granted.
3. Investigate the report that a session could not book a claim. Today `acquire` exits 1 when the resource is busy and books nothing; only `wait` queues. Find what else refuses a booking: self_blocked (two claims from one session conflict, opencoti bug-4004), reuse, or capacity. Every booking should get a queue position and a notification when granted, so sessions queue FIFO behind each other. Consider `acquire --queue` / `book`, which returns a booked claim id at once with the waiter running in the background.

Policy stays in model.py (`decide()` is strict FIFO). Every write goes through `ResourceStore._run()`.

- [ ] the root cause of the failed booking is found and logged
