- `episodic-memory/` is a git subtree of obra/episodic-memory (imported at upstream `7e06519`, v1.6.0+2, on 2026-09-26) with our patches on top. Never point the server at an out-of-tree checkout — the previous one went 79 commits stale and its native module was unloadable for 12 days while `/health` still said OK.
- Upstream's conventions apply inside the directory (its own `CLAUDE.md`): edit `src/`, run `npm run build`, commit `src/` and `dist/` together. `npx vitest run` is its suite (as root, one `chmod`-based file-lock test fails by design).
- `scripts/deploy.py` never runs `npm run build` — `dist/` is committed, and rebuilding in deploy dirties the tree with dependency drift. It builds on the server host only (`episodic.mode == "server"` in `config/claude-hooks.json`), before services, so `episodic-server` restarts onto the new copy.
- `install_vendored()` in `scripts/episodic_doctor.py` = `npm install` with a C++20 compiler + static C++ runtime when the vendored tree or the Node ABI changed (stamp in `node_modules/`), a load check of every host-built `.node` module, then `npm link`. Returns `False` on any failure and writes no stamp for an install that does not load — never a partial success.
- `dist/mcp-server.js` is an esbuild bundle holding `@modelcontextprotocol/sdk`, `zod` and their dependencies, so a dependency fix counts only once `npm run build` has rebuilt it, and `npm audit` cannot see into it. `package-lock.json` is gitignored and the host's own lock keeps old versions, so a transitive fix needs a floor in `overrides`. Check it with the host's lock: `npm install --package-lock-only`, then `npm audit`.
- `scripts/verify_deploy.py` FAILs on the server host when `linked_root()` is not `VENDORED`; `tests/test_deploy_completeness.py` asserts `step_episodic(` precedes `step_services(` and that `check_episodic` exists. A new deployable artifact class gets a test there first.
- Pull upstream / extract our patches for an upstream PR:
  ```bash
  git remote add episodic-upstream https://github.com/obra/episodic-memory.git  # once
  git subtree pull --prefix=episodic-memory episodic-upstream main
  git subtree split --prefix=episodic-memory -b episodic-split
  ```
- Our patches (upstreamable): `EPISODIC_MEMORY_TOOL_INPUT_CHARS` (default 0) caps stored tool inputs/results; `episodic-memory compact [--dry-run] [--no-backup]` applies the cap to existing rows (`VACUUM INTO` + rename, backup at `<db>.pre-compact`).
- Archived transcripts may be stored as `<name>.jsonl.zst`; the canonical name stays `.jsonl` everywhere (DB `archive_path`, `-summary.txt`). Inside `episodic-memory/src`, open transcripts only through `src/transcript-io.ts`, and call `removeCompressedCopy` after writing a fresh archive copy. Sync compresses idle files when `EPISODIC_MEMORY_COMPRESS_AFTER_DAYS` is set; claude-hooks sets it from `episodic.compress_after_days` (default 7, `0` = never) in `session_end.sync_env()` and `episodic_server/server.py:sync_env()` (the server reads `config/claude-hooks.json`, or the file named by `CLAUDE_HOOKS_CONFIG`). `/ingest` drops a stale `.zst`. Live transcripts under `~/.claude/projects` are never compressed. The first bulk run over an existing archive is done by hand — `episodic-memory compress-archive --dry-run`, then without — not inside a SessionEnd-triggered sync.
- After an encoder change run one sync with the migration batch raised (`EPISODIC_MEMORY_MIGRATION_BATCH=60000 episodic-memory sync`); the default 500 per sync leaves new-encoder queries compared against old-encoder vectors until it finishes. Runbook: `docs/episodic-server.md`.
- The embedding model cache is `getModelCacheDir()` (`src/paths.ts`): `EPISODIC_MEMORY_MODEL_CACHE`, else `<superpowers>/models`; `initEmbeddings()` sets `transformers.env.cacheDir` to it. Never leave it at transformers.js's default (`.cache` inside its package): `npm install` deletes it and the sandboxed server cannot write there, so search and indexing failed for 26 days (2026-10-31 .. 11-26). Tests share `node_modules/.cache/episodic-test-models` (`test/setup-isolated-config.ts`). Spec: `test/model-cache-dir.test.ts`.
- `/health` probes with a vector search (`PROBE_ARGS` in `episodic_server/server.py`), never `stats`, which does not load the model. On the server host SessionEnd asks `POST /sync?background=1` (URL from `claude_hooks/episodic_url.py`, shared with `verify_deploy`) and spawns `sync --background` itself only when the server does not answer 202: the hook daemon (`ProtectSystem=strict`) cannot write the sync log, archive or index. Tests: `tests/test_episodic_server.py`, `tests/test_handlers.py`, `tests/test_episodic_url.py`.
- Result formatting never reads a transcript: the line count is `SearchResult.lastLine` / `MultiConceptResult.lastLine` from `lastIndexedLines()` (one query over `idx_archive_path`) in `src/search.ts`. A live transcript can be gigabytes (one 6.4 GB file made every search ~97 s). Spec: `test/search-last-line.test.ts`.
- `episodic_server/server.py` is a `ThreadingHTTPServer` (`EpisodicServer`): `/health` never probes in a plain request (`refresh_probe_in_background()`; `?fresh=1` waits), and reports `searches` (`search_slot()`, `EPISODIC_MAX_SEARCHES`), `indexing` (the sync lock: `SYNC_LOCK` + its proper-lockfile `.lock` dir, stale after 600 s), `last_sync` (parsed from the sync log) and the index size. A last sync with `indexing_skipped` is `degraded`, and `verify_deploy` fails on it. Tests: `tests/test_episodic_server.py`, `tests/test_episodic_url.py`.
