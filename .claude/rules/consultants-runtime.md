- The stall monitor, the deadline, the live round and reroute caps and the xauto escalator all read `state["runtime_control"]`. Every reader treats a missing record as "not configured", so a runner that doesn't seed it switches all of them off without an error. Both runners in `consultants/server/runner.py` seed it through `_seed_runtime_control()`, which is built from `runtime_control_defaults()` in `consultants/engine/control.py`. A new runner path must seed it as well.
- `enabled_roles` on the seeded record lists the roles this run actually has. The runner drops the critic below high effort, except for `xauto`. xauto starts on the medium base, but its escalator is wired only when a critic exists (`use_escalator` in `consultants/engine/graph.py`), so dropping the critic there stops it from ever escalating.
- Any key a node reads, such as `confidence`, must be declared in the production `CouncilState`. LangGraph drops undeclared keys without an error.
- Per-call stall thresholds come from `runtime_stall_thresholds(model)` in `consultants/engine/stall_defaults.py`. It uses production latency (`PRODUCTION_HARD_CAPS_BY_MODEL`, floored at `PRODUCTION_STALL_FLOOR_S`), not the toy-question bench table. A value set on `runtime_control` (via `POST /control`) is an operator override and wins. Recalibrate the table from `transcript.db` `llm_call` rows, never from the bench.
- Hard deadlines are 20 / 60 / 90 min for medium / high / max, plus extra time per fan-out model. They sit above p90 of completed councils. Don't lower them below the measured p90.
- `chat_streamed` (`claude_hooks/get_advice/chat_client.py`) counts content, reasoning and tool-call chunks as liveness. It concatenates every reasoning delta.
- Tool loops size every call. `LoopConfig.prepare_payload` (`claude_hooks/agent_loop/runner.py`) runs before each `chat_fn` call and may rewrite the payload (compact `messages`, set `options.num_predict`). The consultants loops pass `_loop_payload_budgeter()`, and caliber and the advisor pass `None`. If it raises, the error is logged and the call is sent unprepared.
- Compaction must never keep a `tool` message whose assistant `tool_calls` was elided. OpenAI-compatible backends reject the orphan.
- `consultants/server/tool_cache.py` is a per-run cache shared across fan-out lanes. A follow-up gets a fresh one. It covers only the tools in `CACHEABLE_TOOLS` (`survey_project` / `list_files` / `read_file` / `glob` / `grep`). `read_file` is keyed on size and mtime. Any tool that isn't read-only clears the cache. Errors are not cached, and identical concurrent calls run once. `recall_memory` is read-only but never cached (`READ_ONLY_UNCACHED`), because lanes write findings into that store while the run is going.
- Councils are durable. Runs checkpoint to `<cwd>/.claude-hooks/consultants/<sid>/checkpoints.db` (`runner._open_checkpointer`, falling back to `MemorySaver`). Every submitted run is recorded in `~/.claude/consultants-inflight.json` (`consultants/server/inflight.py`; `CONSULTANTS_INFLIGHT_PATH` overrides it, and `tests/conftest.py` isolates it per test).
  - On shutdown, `suspend_running_councils` calls `RunControl.request_suspend()`. The node gate raises `RunSuspended`, and the runner sets `status = "suspended"` without finalizing.
  - At startup, `resume_inflight_councils` resubmits each record with `runner_input["resume"] = True`, which makes `_drive_council_stream` call `stream(None)`.
  - A finished run's record and checkpoint are removed in `_settle_inflight`. A new runner path must go through `_submit_run` and register a record. Tests: `tests/test_consultants_durable_runs.py`.
