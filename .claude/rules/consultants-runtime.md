- The stall monitor, the deadline, the live round and reroute caps and the xauto escalator all read `state["runtime_control"]`. Every reader treats a missing record as "not configured", so a runner that doesn't seed it switches all of them off without an error. Both runners in `consultants/server/runner.py` seed it through `_seed_runtime_control()`, which is built from `runtime_control_defaults()` in `consultants/engine/control.py`. A new runner path must seed it as well.
- `enabled_roles` on the seeded record lists the roles this run actually has. The runner drops the critic below high effort, except for `xauto`. xauto starts on the medium base, but its escalator is wired only when a critic exists (`use_escalator` in `consultants/engine/graph.py`), so dropping the critic there stops it from ever escalating.
- Any key a node reads, such as `confidence`, must be declared in the production `CouncilState`. LangGraph drops undeclared keys without an error.
- Per-call stall thresholds come from `runtime_stall_thresholds(model)` in `consultants/engine/stall_defaults.py`. It uses production latency (`PRODUCTION_HARD_CAPS_BY_MODEL`, floored at `PRODUCTION_STALL_FLOOR_S`), not the toy-question bench table. A value set on `runtime_control` (via `POST /control`) is an operator override and wins. Recalibrate the table from `transcript.db` `llm_call` rows, never from the bench.
- Hard deadlines are 20 / 60 / 90 min for medium / high / max, plus extra time per fan-out model. They sit above p90 of completed councils. Don't lower them below the measured p90.
- `chat_streamed` (`claude_hooks/get_advice/chat_client.py`) counts content, reasoning and tool-call chunks as liveness. It concatenates every reasoning delta.
- `chat` and `chat_streamed` share one retry loop (`_call`): `Retry-After` on 429/503 (capped at 30 s), an empty reply re-asked up to 2 times without spending a retry, and one retry at a provider-named output ceiling, remembered per server and model (`learned_output_ceiling()`). A call that fails for good raises `ChatFault` with `fault_class` (`transport` / `refusal` / `model_missing` / `context_overflow` / `bad_request`); `model_missing` is never retried. Every successful call returns `timings` (also `client.last_timings`), which `consultants/engine/recorder.py` mirrors on the `llm_call` event.
- Roles can run on a server other than the engine's default through named endpoints: an `[endpoints.<name>]` entry in the consultants config (`url`, `backend` = `opencoti` / llama.cpp / xOllama / Ollama), referenced as `@name` or `@name/<model>`. No host defaults are shipped. `OpenAICompatChatClient` (`claude_hooks/get_advice/chat_client.py`) speaks `/v1/chat/completions` and reuses `ChatClient`'s retry loop. A role whose models span several backends gets a `ModelRoutingChatClient`, because fan-out lanes and fallbacks reuse the role's client with another model. Managed with `claude-consultants config set-endpoint` / `remove-endpoint`.
- What a backend can do comes from `claude_hooks/provider_caps.py` (one `ProviderCaps` per `(base_url, model)`, from `/api/show`, `/api/tags`, model recommendations, `/api/xollama`, opencoti `/props` — including `total_slots` and the `opencoti.kv` fields `kv_pool_cells` / `session_ctx_max` / `largest_admissible`) and `claude_hooks/ollama_account.py` (plan via `/api/me`, cloud windows / max output / thinking values). `_fetch_plan()` in `claude_hooks/ollama_slots.py` asks the local server's `/api/me` first and signs `ollama.com/api/me` itself only when that fails. Every probe is soft: an unanswered field is `None`, meaning unknown — never substitute a small default, never guess from a model's name, never branch on a version. Network failures are not cached; definite answers (a 404 included) are. `claude-consultants account` shows the plan and per-model limits.
- Tool loops size every call. `LoopConfig.prepare_payload` (`claude_hooks/agent_loop/runner.py`) runs before each `chat_fn` call and may rewrite the payload (compact `messages`, set `options.num_predict`). The consultants loops pass `_loop_payload_budgeter()`, and caliber and the advisor pass `None`. If it raises, the error is logged and the call is sent unprepared.
- Compaction must never keep a `tool` message whose assistant `tool_calls` was elided. OpenAI-compatible backends reject the orphan.
- `consultants/server/tool_cache.py` is a per-run cache shared across fan-out lanes. A follow-up gets a fresh one. It covers only the tools in `CACHEABLE_TOOLS` (`survey_project` / `list_files` / `read_file` / `glob` / `grep`). `read_file` is keyed on size and mtime. Any tool that isn't read-only clears the cache, except a tool in `ISOLATED_EFFECT_TOOLS` (`run_command`), which diverges only the calling lane; that lane then reads privately. Errors are not cached, and identical concurrent calls run once. `recall_memory` is read-only but never cached (`READ_ONLY_UNCACHED`), because lanes write findings into that store while the run is going. A tool pinned to a non-`auto` permission skips the cache, so a cached hit cannot bypass a live deny.
- Tool permissions set by `POST /control` reach a running council: `RunControl` (`consultants/engine/run_control.py`) holds the live copy, the runner hands it to `build_tool_surface` as a per-call source, and a resume re-seeds it from the checkpoint. The gate's ladder has four levels; legacy `allow` / `ask` are stored as `auto` / `ask_human`. `LaneBoundExecutor` (`consultants/engine/lane_executor.py`) binds the researcher / tool_executor lane id to the shared executor.
- `consultants/server/session_gc.py` collects `coder-out/` trees (`DEFAULT_CODER_OUT_TTL_DAYS` = 30) and empty session dirs at council end, in an hourly reaper sweep and via `claude-consultants gc`. Session records and in-flight councils are never touched. `scripts/sandbox_probe.py` reports the host's sandbox capabilities.
- Councils are durable. Runs checkpoint to `<cwd>/.claude-hooks/consultants/<sid>/checkpoints.db` (`runner._open_checkpointer`, falling back to `MemorySaver`). Every submitted run is recorded in `~/.claude/consultants-inflight.json` (`consultants/server/inflight.py`; `CONSULTANTS_INFLIGHT_PATH` overrides it, and `tests/conftest.py` isolates it per test).
  - On shutdown, `suspend_running_councils` calls `RunControl.request_suspend()`. The node gate raises `RunSuspended`, and the runner sets `status = "suspended"` without finalizing.
  - At startup, `resume_inflight_councils` resubmits each record with `runner_input["resume"] = True`, which makes `_drive_council_stream` call `stream(None)`.
  - A finished run's record and checkpoint are removed in `_settle_inflight`. A new runner path must go through `_submit_run` and register a record. Tests: `tests/test_consultants_durable_runs.py`.
