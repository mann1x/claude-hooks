- The stall monitor, the deadline, the live round and reroute caps and the xauto escalator all read `state["runtime_control"]`. Every reader treats a missing record as "not configured", so a runner that doesn't seed it switches all of them off without an error. Both runners in `consultants/server/runner.py` seed it through `_seed_runtime_control()`, which is built from `runtime_control_defaults()` in `consultants/engine/control.py`. A new runner path must seed it as well. Every `Send` payload must carry `runtime_control` too, or each fanned-out lane runs without stall monitoring, the typed protocol and budget / think / sampling settings (AST guard in `tests/test_council_live_fixes.py`).
- `enabled_roles` on the seeded record lists the roles this run actually has. The runner drops the critic below high effort, except for `xauto`. xauto starts on the medium base, but its escalator is wired only when a critic exists (`use_escalator` in `consultants/engine/graph.py`), so dropping the critic there stops it from ever escalating.
- Any key a node reads, such as `confidence`, must be declared in the production `CouncilState`. LangGraph drops undeclared keys without an error. A channel several lanes can write in one step needs a reducer: `error` (`join_errors`) and `_role_failed` (`latest_non_none`) in `consultants/engine/state_v2.py`; as plain channels, two lanes failing together aborted the run with `InvalidUpdateError`.
- Per-call stall thresholds come from `runtime_stall_thresholds(model)` in `consultants/engine/stall_defaults.py`. It uses production latency (`PRODUCTION_HARD_CAPS_BY_MODEL`, floored at `PRODUCTION_STALL_FLOOR_S`), not the toy-question bench table. The researcher's tuned hard cap scales with `num_predict / 32768`, because hard caps are not retried; an operator `per_lane_hard_s` is used as set. A value set on `runtime_control` (via `POST /control`) is an operator override and wins. Recalibrate the table from `transcript.db` `llm_call` rows, never from the bench.
- Hard deadlines are 20 / 60 / 90 min for medium / high / max, plus extra time per fan-out model. They sit above p90 of completed councils. Don't lower them below the measured p90.
- `chat_streamed` (`claude_hooks/get_advice/chat_client.py`) counts content, reasoning and tool-call chunks as liveness. It concatenates every reasoning delta.
- `chat` and `chat_streamed` share one retry loop (`_call`): `Retry-After` on 429/503 (capped at 30 s), an empty reply re-asked up to 2 times without spending a retry, and one retry at a provider-named output ceiling, remembered per server and model (`learned_output_ceiling()`). A call that fails for good raises `ChatFault` with `fault_class` (`transport` / `refusal` / `model_missing` / `context_overflow` / `bad_request`); `model_missing` is never retried. Every successful call returns `timings` (also `client.last_timings`), which `consultants/engine/recorder.py` mirrors on the `llm_call` event.
- Roles can run on a server other than the engine's default through named endpoints: an `[endpoints.<name>]` entry in the consultants config (`url`, `backend` = `opencoti` / llama.cpp / xOllama / Ollama), referenced as `@name` or `@name/<model>`. No host defaults are shipped. `OpenAICompatChatClient` (`claude_hooks/get_advice/chat_client.py`) speaks `/v1/chat/completions` and reuses `ChatClient`'s retry loop; it maps `format` to `response_format` and re-sends without it when the server refuses. llama.cpp templates accept one leading system turn, so on the OpenAI-compat and llamafile wires `single_system_messages()` joins the leading system run and turns later system messages into user notes. A role whose models span several backends gets a `ModelRoutingChatClient`, because fan-out lanes and fallbacks reuse the role's client with another model. Managed with `claude-consultants config set-endpoint` / `remove-endpoint`.
- Typed messages between roles (`[protocol] typed`, default off; off is byte-identical; `claude-consultants config set-protocol --typed on|off`): planner / researcher / critic + meta_critic / adversary hand in `council_plan` / `council_report` / `council_verdict` / `council_refutation` through the agent loop's `result_tools`, answered by the engine (`consultants/engine/typed_results.py`). A record counts only as the turn's only call; invalid or cut args are re-asked once, then the role falls back to prose. Records are rendered back into the prose the existing parsers read — never hand raw JSON to a downstream role, and never put `maxLength` in a schema (cut text at render). The flag reaches the graph as `runtime_control.typed_protocol`, seeded only when on.
- Output cap and window (`consultants/engine/budget.py`): `resolve_output_budget()` = min(0.75 × window, 96k, model max), 32k with no window; `reserve_tokens()` = max(1024, 0.12 × estimate). `resolve_window()` order: granted > pinned (legacy explicit `ctx_max`) > opencoti `session_ctx_max` / `n_ctx` > cloud recommendations / trained > local Modelfile `num_ctx` > 32768; local Ollama gets the same resolved `num_ctx` on every call. A local xOllama window is Modelfile `num_ctx`, else the loaded window from `/api/ps` (60 s cache), else the default — never the trained context. The role's cap is stated once in its system prompt (`# Output Budget`, `with_output_budget_section()`), stable across calls so the prefix cache survives. `[endpoints.X] window = "dynamic"` is the default; `assured` is refused. Knobs merge `[budget]` > `[role.X.budget]` > `[role.X.models."<m>"]` (`knobs_from()`), seeded into `runtime_control.budget` only when set; managed with `claude-consultants config set-budget`.
- Thinking (`think` = `false` / `true`/`auto` / `minimal`..`max` (`xhigh` = `max`) / a token count) is set per role and per `[role.X.models."<m>"]`, and never derived from effort. Precedence: explicit role setting > model template `think` > role default; an explicit role value is seeded as `runtime_control.think["<role>"]`, only when set. Ollama gets a level only when the model's cached `thinking_values` accept it, else `think: true`; a count is `think: true` + `options.think_budget`. A refused level is retried once as `think: true`; only a refused `true` strips the field. opencoti / llama.cpp map a level to `reasoning_budget_tokens` with Ollama's fractions of min(`num_predict`, window). On xOllama the enforced budget is asked before the call via `POST /api/show` (`ChatClient.think_budget`, never asked of cloud) and `timings.think_budget_tokens` is read back from the reply, streamed included; elsewhere it is sent. The `# Output Budget` section states it. Capped-thinking detection compares against that allowance (`num_predict` only when none is known). Managed with `claude-consultants config set-think`.
- Sampling diversity (`consultants/engine/sampling_diversity.py`): every role instance (each lane, each role turn) gets its own sampler from `allocate()`, called through `_instance_sampling()` in `consultants/engine/council.py`; a lane's loop and summary share one instance, and an explicit option wins. `seed = "random"` (default) draws from [0, 2^31) and never repeats for the same model in one run; an integer `s` gives the i-th same-model instance `s + i`; `"off"` sends none. Temperature base = explicit > model template > Modelfile / `/props`, unset when none is known, jittered by `temperature_range_pct` (default 2, clamped to 10). `seed = "off"` + range 0 adds nothing to a request. Uniqueness is scoped by `runtime_control.sampling_run` (always seeded, declared in `consultants/engine/state_v2.py`, rides the checkpoint); layers `[sampling]` > `[role.X.sampling]` > `[role.X.models."<m>"]` are seeded as `runtime_control.sampling` only when set. Realized values land in `timings.sampler`. Managed with `claude-consultants config set-sampling`.
- Compaction (`consultants/engine/compaction.py`, plan C) runs only through `compact(Scope, …)`: `Scope` holds the role's own `(chat_client, model)` and nothing else, every step is serial with `think: False`, calls are recorded as `<role>:compaction` and stall-protected with `phase: "compaction"` (overrides `compaction_stall_threshold_s` / `compaction_hard_s` on `runtime_control`); a failed step keeps what it had and never fails the lane. Flows: `reduced` (default: present-tense replay writer → retrospective → reviewer), `full` (halfway marker → retrospective → two serial half-critics → synthesizer), `basic` (no call). The digest aims at `compaction_target_tokens()` = 0.25 × (window − system + tool overhead), below the trigger (`trigger_ratio` 0.9, `output_room_min` 8000, reply reserve measured from the transcript with the recent-3 / second-largest rule). `plan_cut()` keeps the head (system + question), pins the latest typed prompt when its turn is folded, and starts the tail on an assistant turn or typed prompt, never a `tool` message. A keep-tail result over the trigger is re-run with no tail (`FULL_PROMPT`) and the smaller kept; a fold that does not shrink is discarded. The marker carries `_compaction_user_requests` and `_compaction_ledger` across generations; `[#N]` citations are spliced by `tool_ledger.splice()`. Settings: `[compaction]` > `[role.X.compaction]` > `[role.X.models."<m>"]`, seeded as `runtime_control.compaction` only when set, riding `Knobs.compaction` from `_budget_knobs()`; managed with `claude-consultants config set-compaction`. Tests: `tests/test_compaction_flows.py`.
- Overflow (plan C5): before sizing, `history.tidy()` (`consultants/engine/history.py`) middle-truncates tool results past `tool_result_max_chars` (32000; `read_file` 50000) with a marker naming the harness, and rewrites superseded `read_file` results to `[outdated - see the latest file content]` only once the history fills `stale_read_share` (0.4) of the window, all at once. A provider `ChatFault` with `fault_class == "context_overflow"` forces one compaction with `require_smaller` (basic fold as the floor, the digest kept only if smaller and under the trigger) and one resend — `_single_shot` inline, tool loops through `_loop_payload_budgeter(...).recover(chat_fn)`; a second refusal raises `ContextOverflowUnrecovered`. A prompt count ≥ 0.85 of the window that is ≥ 1.15× short of the estimate is a silent truncation: never calibrated on, and the next call compacts first. A thin window-bound cap forces one compaction per descent (`_starved_cap`). The per-model `note_output_cap` / `consume_context_overflow` globals are gone. The agent loop's duplicate stub keys on canonical args, re-serves every 4th repeat, and clears on any write tool and on compaction.
- Thinking (plan C4): `[compaction] reasoning_replay` = `none` (default, reasoning dropped from history) / `all` (kept; `claude_hooks/reasoning_replay.py` probes first and falls back to `inline` where the template drops the field) / `inline` (`<think>…</think>` in content), passed as `LoopConfig.reasoning_replay`. A cut answer or a force-first re-ask whose thinking ran to its allowance hands its condensed note back in the replacing request (`as_discarded_turn_note`), in tool loops and in `_single_shot`; every harness text quoting past reasoning says it is not carried (`REASONING_NOT_CARRIED`). Harness-written user turns carry `_harness: True`, so the cut planner never takes them for typed prompts. Tests: `tests/test_compaction_overflow.py`, `tests/test_compaction_thinking.py`.
- Decision models (plan H): `claude_hooks/decision_client.py` speaks `/v1/systemone` to TypeSafe's Jev (Bearer key) and Ollama ≥ 0.35 / xOllama (no key; `/api/version` probe; 64 KiB body and loaded-window cut-and-retry; ≤ 26 options). `[decision]` (off by default; `claude-consultants config set-decision`, `decision-models`) is seeded as `runtime_control.decision` only when on, with `key_file` — never the key. Every seam goes through `consultants/engine/decision.py:ask()`, which never raises and records a `decision` event: `review` + `confidence` in one call at the synthesizer (`_synthesizer_decision_seams` → `decision_review` state, declared in both state classes → `ConsultationResult.decision` → `result` / `show`), `confidence` at the critic and meta-critic (`_scored_critic_confidence`; a scored value replaces the self-rating on the `confidence` channel, a 0.0 included), `struggle` in the researcher loop (`_struggle_watch` wraps the budgeter; one `_harness` nudge per lane at the high-stakes floor; returns the budgeter itself when off), `citations` after the CitationLinter (`semantic_items` / `annotate_unsupported`). Score criteria are a list; both dialects refuse a map. Tests: `tests/test_decision_client.py`, `tests/test_decision_seams.py`; bench `benchmarks/consultants/decision_bench.py`.
- Reasoning-loop guard (plan D1, `claude_hooks/reasoning_loop_guard.py`, a port of the fork's `reasoning-loop-guard.ts` with its thresholds) is always on, on every backend, in no profile. Both stream readers in `claude_hooks/get_advice/chat_client.py` feed it every reasoning delta and stop reading on a trip (leaving `with urlopen` closes the connection, which stops the billing); the reply carries `done_reason = "reasoning_loop"` verbatim plus `reasoning_loop` (also in `timings`). An unstreamed reply is scanned after the fact and counts only when the reasoning ate the turn. `run_loop` keeps the partial content, condenses the reasoning from before the loop, adds a `_harness` `[SYSTEM MESSAGE]` and continues; `reasoning_loop_max_trips` (3) cut turns in a row strip the tools and ask one report with `think: False`, marked `_stop_reason` / `_failure_class` = `reasoning_loop`. A cut turn is never force-first re-asked or continued as truncated. Each trip and stop goes to `LoopConfig.on_guard`; consultants roles pass `guard_sink()` (`consultants/engine/recorder.py`), which records `kind="guard"` events. Length is never the signal. The milder case, a paragraph re-derived verbatim while the turn still calls tools, is `claude_hooks/reasoning_repetition.py`: both thresholds required, prose paragraphs only, one nudge per lane with a cooldown and an earned-back budget, appended after the turn's tool results; it never cuts. Tests: `tests/test_reasoning_loop_guard.py`, `tests/test_reasoning_repetition.py`.
- What a backend can do comes from `claude_hooks/provider_caps.py` (one `ProviderCaps` per `(base_url, model)`, from `/api/show`, `/api/tags`, model recommendations, `/api/xollama`, opencoti `/props` — including `total_slots` and the `opencoti.kv` fields `kv_pool_cells` / `session_ctx_max` / `largest_admissible`) and `claude_hooks/ollama_account.py` (plan via `/api/me`, cloud windows / max output / thinking values). `_fetch_plan()` in `claude_hooks/ollama_slots.py` asks the local server's `/api/me` first and signs `ollama.com/api/me` itself only when that fails. Every probe is soft: an unanswered field is `None`, meaning unknown — never substitute a small default, never guess from a model's name, never branch on a version. Network failures are not cached; definite answers (a 404 included) are. `claude-consultants account` shows the plan and per-model limits.
- Tool loops size every call. `LoopConfig.prepare_payload` (`claude_hooks/agent_loop/runner.py`) runs before each `chat_fn` call and may rewrite the payload (compact `messages`, set `options.num_predict`). The consultants loops pass `_loop_payload_budgeter()`, and caliber and the advisor pass `None`. If it raises, the error is logged and the call is sent unprepared.
- Compaction must never keep a `tool` message whose assistant `tool_calls` was elided. OpenAI-compatible backends reject the orphan.
- `consultants/server/tool_cache.py` is a per-run cache shared across fan-out lanes. A follow-up gets a fresh one. It covers only the tools in `CACHEABLE_TOOLS` (`survey_project` / `list_files` / `read_file` / `glob` / `grep`). `read_file` is keyed on size and mtime. Any tool that isn't read-only clears the cache, except a tool in `ISOLATED_EFFECT_TOOLS` (`run_command`), which diverges only the calling lane; that lane then reads privately. Errors are not cached, and identical concurrent calls run once. `recall_memory` is read-only but never cached (`READ_ONLY_UNCACHED`), because lanes write findings into that store while the run is going. A tool pinned to a non-`auto` permission skips the cache, so a cached hit cannot bypass a live deny.
- Tool permissions set by `POST /control` reach a running council: `RunControl` (`consultants/engine/run_control.py`) holds the live copy, the runner hands it to `build_tool_surface` as a per-call source, and a resume re-seeds it from the checkpoint. The gate's ladder has four levels; legacy `allow` / `ask` are stored as `auto` / `ask_human`. `LaneBoundExecutor` (`consultants/engine/lane_executor.py`) binds the researcher / tool_executor lane id to the shared executor.
- `consultants/server/session_gc.py` collects `coder-out/` trees (`DEFAULT_CODER_OUT_TTL_DAYS` = 30) and empty session dirs at council end, in an hourly reaper sweep and via `claude-consultants gc`. Session records and in-flight councils are never touched. `scripts/sandbox_probe.py` reports the host's sandbox capabilities.
- Councils are durable. Runs checkpoint to `<cwd>/.claude-hooks/consultants/<sid>/checkpoints.db` (`runner._open_checkpointer`, falling back to `MemorySaver`). Every submitted run is recorded in `~/.claude/consultants-inflight.json` (`consultants/server/inflight.py`; `CONSULTANTS_INFLIGHT_PATH` overrides it, and `tests/conftest.py` isolates it per test).
  - On shutdown, `suspend_running_councils` calls `RunControl.request_suspend()`. The node gate raises `RunSuspended`, and the runner sets `status = "suspended"` without finalizing.
  - At startup, `resume_inflight_councils` resubmits each record with `runner_input["resume"] = True`, which makes `_drive_council_stream` call `stream(None)`.
  - A finished run's record and checkpoint are removed in `_settle_inflight`. A new runner path must go through `_submit_run` and register a record. Tests: `tests/test_consultants_durable_runs.py`.
