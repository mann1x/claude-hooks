- The stall monitor, the deadline, the live round and reroute caps and the xauto escalator all read `state["runtime_control"]`. Every reader treats a missing record as "not configured", so a runner that doesn't seed it switches all of them off without an error. Both runners in `consultants/server/runner.py` seed it through `_seed_runtime_control()`, which is built from `runtime_control_defaults()` in `consultants/engine/control.py`. A new runner path must seed it as well. Every `Send` payload must carry `runtime_control` too, or each fanned-out lane runs without stall monitoring, the typed protocol and budget / think / sampling settings (AST guard in `tests/test_council_live_fixes.py`).
- `enabled_roles` on the seeded record lists the roles this run actually has. The runner drops the critic below high effort, except for `xauto`. xauto starts on the medium base, but its escalator is wired only when a critic exists (`use_escalator` in `consultants/engine/graph.py`), so dropping the critic there stops it from ever escalating.
- Any key a node reads, such as `confidence`, must be declared in the production `CouncilState`. LangGraph drops undeclared keys without an error. A channel several lanes can write in one step needs a reducer: `error` (`join_errors`) and `_role_failed` (`latest_non_none`) in `consultants/engine/state_v2.py`; as plain channels, two lanes failing together aborted the run with `InvalidUpdateError`.
- Per-call stall thresholds come from `runtime_stall_thresholds(model)` in `consultants/engine/stall_defaults.py`. It uses production latency (`PRODUCTION_HARD_CAPS_BY_MODEL`, floored at `PRODUCTION_STALL_FLOOR_S`), not the toy-question bench table. The researcher's tuned hard cap scales with `num_predict / 32768`, because hard caps are not retried; an operator `per_lane_hard_s` is used as set. A value set on `runtime_control` (via `POST /control`) is an operator override and wins. Recalibrate the table from `transcript.db` `llm_call` rows, never from the bench. A model with no measured row can borrow another's through `THRESHOLD_INHERITANCE` (glm-5.3-flash → glm-5.2); unlike `MODEL_SUCCESSIONS` it reroutes nothing.
- Hard deadlines are 20 / 60 / 90 min for medium / high / max, plus extra time per fan-out model. They sit above p90 of completed councils. Don't lower them below the measured p90.
- `chat_streamed` (`claude_hooks/get_advice/chat_client.py`) counts content, reasoning and tool-call chunks as liveness. It concatenates every reasoning delta.
- `chat` and `chat_streamed` share one retry loop (`_call`): `Retry-After` on 429/503 (capped at 30 s), an empty reply re-asked up to 2 times without spending a retry (the resend carries `EMPTY_TURN_REMINDER` once, so a fixed seed does not return the same nothing), and one retry at a provider-named output ceiling, remembered per server and model (`learned_output_ceiling()`). A call that fails for good raises `ChatFault` with `fault_class` (`transport` / `refusal` / `model_missing` / `context_overflow` / `bad_request` / `tool_call_unparsable`); `model_missing` and `tool_call_unparsable` are never retried. Every successful call returns `timings` (also `client.last_timings`), which `consultants/engine/recorder.py` mirrors on the `llm_call` event.
- A long wait on infrastructure is reported, never acted on (plan D9): `chat_streamed(on_wait=)` gets one dict per threshold in `INFRA_WAIT_NOTICE_S` (`claude_hooks/ollama_slots.py`, 600 s then 7200 s, tracked by `infra_notices()`) crossed while queued for a connection slot (`slot(on_wait=)`, `what: "slot"`) or sleeping through a network outage (`_wait_out_outage`, `what: "outage"`). `make_stall_protected_chat_fn` (`consultants/engine/stall_chat.py`) records it as the lane's `infra_wait` event; the run deadline still decides the lane's fate. Tests: `tests/test_infra_wait.py`.
- Roles can run on a server other than the engine's default through named endpoints: an `[endpoints.<name>]` entry in the consultants config (`url`, `backend` = `opencoti` / llama.cpp / xOllama / Ollama), referenced as `@name` or `@name/<model>`. No host defaults are shipped. `OpenAICompatChatClient` (`claude_hooks/get_advice/chat_client.py`) speaks `/v1/chat/completions` and reuses `ChatClient`'s retry loop; it maps `format` to `response_format` and re-sends without it when the server refuses. llama.cpp templates accept one leading system turn, so on the OpenAI-compat and llamafile wires `single_system_messages()` joins the leading system run and turns later system messages into user notes. A role whose models span several backends gets a `ModelRoutingChatClient`, because fan-out lanes and fallbacks reuse the role's client with another model. Managed with `claude-consultants config set-endpoint` / `remove-endpoint`.
- Reports are numbered and attributed in every mode: `RESEARCHER REPORT N (lane L, round R)` (`report_tags()`, from `research_lanes`, whose entries carry `lane` and `round`); never label a report `(round i)` by its index. With the typed flag: `typed_results.verify_claims()` checks each report claim at the source and the researcher then skips the regex lint for it; judges with tools get the cache-only `evidence` tool (`read_evidence.with_evidence`, `SharedReadCache.snapshot()`); `barren_rounds()` ≥ `STALL_ROUNDS` overrules a re-route; a follow-up starts at `follow_up_route` (`GraphDeps.follow_up_route`, set by the runner, never for retry-lanes; `follow_up_route` declared in both state classes). `consult --tried` / body `tried` (`parse_tried()`, 400 on a bad shape) reaches every role as one `already_tried` Doc (`runner._tried_docs`). Tests: `tests/test_typed_results.py`, `tests/test_read_evidence.py`, `tests/test_follow_up_route.py`.
- Typed messages between roles (`[protocol] typed`, default off; off is byte-identical; `claude-consultants config set-protocol --typed on|off`): planner / researcher / critic + meta_critic / adversary hand in `council_plan` / `council_report` / `council_verdict` / `council_refutation` through the agent loop's `result_tools`, answered by the engine (`consultants/engine/typed_results.py`). A record counts only as the turn's only call; invalid or cut args are re-asked once, then the role falls back to prose. Records are rendered back into the prose the existing parsers read — never hand raw JSON to a downstream role, and never put `maxLength` in a schema (cut text at render). The flag reaches the graph as `runtime_control.typed_protocol`, seeded only when on.
- Output cap and window (`consultants/engine/budget.py`): `resolve_output_budget()` = min(0.75 × window, 96k, model max), 32k with no window; `reserve_tokens()` = max(1024, 0.12 × estimate). `resolve_window()` order: granted > pinned (legacy explicit `ctx_max`) > opencoti `session_ctx_max` / `n_ctx` > cloud recommendations / trained > local Modelfile `num_ctx` > local trained > 32768; local Ollama gets the same resolved `num_ctx` on every call. A local xOllama window is Modelfile `num_ctx`, else the loaded window from `/api/ps` (60 s cache), else the trained context, else the default. The trained context (`/api/show` `model_info.<arch>.context_length`, answered for unpulled cloud models too, with no pull) is the council's default window; an operator who wants less pins `num_ctx`. 32768 only when nothing is declared. The role's cap is stated once in its system prompt (`# Output Budget`, `with_output_budget_section()`), stable across calls so the prefix cache survives. `[endpoints.X] window = "dynamic"` is the default; `assured` is refused. Knobs merge `[budget]` > `[role.X.budget]` > `[role.X.models."<m>"]` (`knobs_from()`), seeded into `runtime_control.budget` only when set; managed with `claude-consultants config set-budget`.
- Thinking (`think` = `false` / `true`/`auto` / `minimal`..`max` (`xhigh` = `max`) / a token count) is set per role and per `[role.X.models."<m>"]`, and never derived from effort. Precedence: explicit role setting > model template `think` > role default; an explicit role value is seeded as `runtime_control.think["<role>"]`, only when set. Ollama gets a level only when the model's cached `thinking_values` accept it, else `think: true`; `thinking_values` come from the recommendations, else `/api/show` `thinking.values` (`caps_fields_from_show()`): gemma4:31b-cloud declares only on/off and, since 2026-09, ignores a level silently (no reasoning at all); a count is `think: true` + `options.think_budget`. A refused level is retried once as `think: true`; only a refused `true` strips the field. opencoti / llama.cpp map a level to `reasoning_budget_tokens` with Ollama's fractions of min(`num_predict`, window). On xOllama the enforced budget is asked before the call via `POST /api/show` (`ChatClient.think_budget`, never asked of cloud) and `timings.think_budget_tokens` is read back from the reply, streamed included; elsewhere it is sent. The `# Output Budget` section states it. Capped-thinking detection compares against that allowance (`num_predict` only when none is known). Managed with `claude-consultants config set-think`.
- Sampling diversity (`consultants/engine/sampling_diversity.py`): every role instance (each lane, each role turn) gets its own sampler from `allocate()`, called through `_instance_sampling()` in `consultants/engine/council.py`; a lane's loop and summary share one instance, and an explicit option wins. `seed = "random"` (default) draws from [0, 2^31) and never repeats for the same model in one run; an integer `s` gives the i-th same-model instance `s + i`; `"off"` sends none. Temperature base = explicit > model template > Modelfile / `/props`, unset when none is known, jittered by `temperature_range_pct` (default 2, clamped to 10). `seed = "off"` + range 0 adds nothing to a request. Uniqueness is scoped by `runtime_control.sampling_run` (always seeded, declared in `consultants/engine/state_v2.py`, rides the checkpoint); layers `[sampling]` > `[role.X.sampling]` > `[role.X.models."<m>"]` are seeded as `runtime_control.sampling` only when set. Realized values land in `timings.sampler`. Managed with `claude-consultants config set-sampling`.
- Compaction (`consultants/engine/compaction.py`, plan C) runs only through `compact(Scope, …)`: `Scope` holds the role's own `(chat_client, model)` and nothing else, every step is serial with `think: False`, calls are recorded as `<role>:compaction` and stall-protected with `phase: "compaction"` (overrides `compaction_stall_threshold_s` / `compaction_hard_s` on `runtime_control`); a failed step keeps what it had and never fails the lane. Flows: `reduced` (default: present-tense replay writer → retrospective → reviewer), `full` (halfway marker → retrospective → two serial half-critics → synthesizer), `basic` (no call). The digest aims at `compaction_target_tokens()` = 0.25 × (max input − system + tool overhead), below the trigger (`trigger_ratio` 0.9 of max input, `output_room_min` 8000, reply reserve measured from the transcript with the recent-3 / second-largest rule). Max input is `max_input_tokens()` = 0.9 × window (fork `CONTEXT_WINDOW_INPUT_RATIO`); the room trigger subtracts the output room from the window itself. The trigger's declared output room is the model's published ceiling (`model_max_output_of`), else `declared_output_tokens()` = 0.25 × window (fork `resolveDefaultMaxOutputTokens`) — never the per-turn cap `resolve_output_budget()` (0.75 × window), which `plan()` used to pass and which held the trigger at its 0.5 × window floor. `plan_cut()` keeps the head (system + question), pins the latest typed prompt when its turn is folded, and starts the tail on an assistant turn or typed prompt, never a `tool` message. The last-turn ceiling is 0.66 × (max input − overhead), as the fork's `compaction.ts` takes it, never a share of the whole window. A keep-tail result over the trigger is re-run with no tail (`FULL_PROMPT`) and the smaller kept; a fold that does not shrink is discarded. The marker carries `_compaction_user_requests` and `_compaction_ledger` across generations; `[#N]` citations are spliced by `tool_ledger.splice()`. The writer is shown the head's question first (`write_digest(task=)`, shown, never stored) and a span sized from the window (`transcript_budget()`, `context_tokens=`); its key holds every call of the span plus the carried calls evicted to budget — never evict the span's own calls from the key (it narrated calls it never made); `tool_ledger.evicted()` bounds only what is carried, the uncited block keeps the key's numbers, and the key is bounded at max(ledger budget, 0.1 × the writer's input) by shortening inputs (`render_key(max_chars=)`, fork 46bafaeb71). Generation = previous marker's `_compaction_generation` + 1 (`budget.compact_messages`); never count markers. Settings: `[compaction]` > `[role.X.compaction]` > `[role.X.models."<m>"]`, seeded as `runtime_control.compaction` only when set, riding `Knobs.compaction` from `_budget_knobs()`; managed with `claude-consultants config set-compaction`. Tests: `tests/test_compaction_flows.py`.
- Overflow (plan C5): before sizing, `history.tidy()` (`consultants/engine/history.py`) middle-truncates tool results past `tool_result_max_chars` (32000; `read_file` 50000) with a marker naming the harness, and rewrites superseded `read_file` results to `[outdated - see the latest file content]` only once the history fills `stale_read_share` (0.4) of the window, all at once. A provider `ChatFault` with `fault_class == "context_overflow"` forces one compaction with `require_smaller` (basic fold as the floor, the digest kept only if smaller and under the trigger) and one resend — `_single_shot` inline, tool loops through `_loop_payload_budgeter(...).recover(chat_fn)`; a second refusal raises `ContextOverflowUnrecovered`. A prompt count ≥ 0.85 of the window that is ≥ 1.15× short of the estimate is a silent truncation: never calibrated on, and the next call compacts first. A thin window-bound cap forces one compaction per descent (`_starved_cap`). The per-model `note_output_cap` / `consume_context_overflow` globals are gone. The agent loop's duplicate stub keys on canonical args, re-serves every 4th repeat, and clears on any write tool and on compaction. A failed answer (`loop_detection.is_failed_output()`) is never kept for the stub: a call that failed runs again for real, or a read refused once stays refused after it becomes legal.

- Reasoning-loop guard (plan D1, `claude_hooks/reasoning_loop_guard.py`, a port of the fork's `reasoning-loop-guard.ts` with its thresholds) is always on, on every backend, in no profile. Both stream readers in `claude_hooks/get_advice/chat_client.py` feed it every reasoning delta and stop reading on a trip (leaving `with urlopen` closes the connection, which stops the billing); the reply carries `done_reason = "reasoning_loop"` verbatim plus `reasoning_loop` (also in `timings`). An unstreamed reply is scanned after the fact and counts only when the reasoning ate the turn. `run_loop` keeps the partial content, condenses the reasoning from before the loop, adds a `_harness` `[SYSTEM MESSAGE]` and continues; `reasoning_loop_max_trips` (3) cut turns in a row strip the tools and ask one report with `think: False`, marked `_stop_reason` / `_failure_class` = `reasoning_loop`. A cut turn is never force-first re-asked or continued as truncated. Signals: the fork's low-uniqueness / line-cycle / phrase-cycle plus our `block-cycle` (a 7–128-line block repeated ≥ 3 times verbatim over ≥ 6,000 characters), which the replay showed the 60-line window misses. Each trip and stop goes to `LoopConfig.on_guard`; consultants roles pass `guard_sink()` (`consultants/engine/recorder.py`), which records `kind="guard"` events. Length is never the signal. The milder case, a paragraph re-derived verbatim while the turn still calls tools, is `claude_hooks/reasoning_repetition.py`: both thresholds required, prose paragraphs only, one nudge per lane with a cooldown and an earned-back budget, appended after the turn's tool results; it never cuts. Tests: `tests/test_reasoning_loop_guard.py`, `tests/test_reasoning_repetition.py`.
- Tool-call loop guard and mistake limit (plan D10 / D14, `claude_hooks/loop_detection.py`, a port of the fork's `loop-detection.ts`) are always on in `run_loop` through `ToolGuards`: every call is inspected before it runs (consecutive 2 soft / 5 hard; a failing signature counts down 6 strikes across interleaved calls; the same answer 3 times warns, 6 is hard for write tools; `LoopConfig.polling_tools` are exempt). A soft verdict rides on the tool result as `[SYSTEM MESSAGE]`; the first hard one answers the call without running it as a last warning; the second, or `mistake_limit` (10, refit by replay from the fork's 6) failed calls in a row, ends the loop with `_forced_report()` — tools off, think off, `_stop_reason` / `_failure_class` = `loop_guard` / `mistake_limit`, `_loop_call` naming the call. A failure is an answer starting `error` (the convention of every tool surface here), `traceback`, or a JSON `success: false`; a new tool must keep that convention or the strike counter cannot see it. Events go to `on_guard` (`guard_sink()`). Tests: `tests/test_loop_detection.py`.
- Struggle supervisor (plan D2, `claude_hooks/struggle_supervisor.py`, the fork's worker supervisor) is always on in `run_loop`: one nudge on 3 budget-exhausted turns in the last 6, on half of `max_iterations` (floored at 8) only when ≤ 1 of the last 6 calls brought anything new (`close_iteration(calls=)`; the count alone nudged 204 progressing lanes in the replay), or on 3 failures in the last 6 tool results; after a 2-turn grace, 2 more budget-exhausted turns end the loop with `_forced_report()`, `_stop_reason = struggle`. - Silent turns (plan D3, standard, `claude_hooks/silent_turns.py`): in `run_loop`'s no-tool-call branch, after the force-first retry and before truncation continuation, `_SilentTurns.reask()` re-asks a thinking-only turn (≤ 2 in a row; a call written inside the thinking gets its own reminder), a `<tool_call><function=…>` or MiniMax `<invoke name=…>` block left in the text (≤ 2, the attempt kept in history), and an answer ending on a promise of work (1 per lane), each with a `_harness` `[SYSTEM MESSAGE]` and a `silent_turn` guard event; a tool-calling turn resets the streaks. Write scopes (`--write-scope`, `shell.scopes`, `ShellSettings.write_scopes`) switch write mode to `claude_hooks/sandbox/clone_views.py` on any root, git included: a `cp --reflink` clone per scope per lane, bound rw at the scope's real path, a manifest of (kind, size, mtime, mode, owner, clone ctime) taken after the hand-over and after `_past_the_tick()` (the coarse clock would otherwise hide a same-size write); freeze moves changed files into `held/`, apply refuses as a whole on any file changed since the clone and never `rmtree`s a user directory. `session_views()` picks the kind from the scopes or `sandbox.json` `kind`; `sweep()` rebuilds through `_from_record()`. Tests: `tests/test_council_clone_views.py`, live `TestScopedView`; bench `scripts/bench_clone_views.py`. The registry routes a lane's file tools into its view (`view_root()` → `[(real, view), …]` / `_in_view`, which resolves relative `PATH_KEYS` args when the cwd is not mapped in `claude_hooks/tool_registry/registry.py`). The static launcher `native/council-sandbox` (Rust, no crates, musl, non-PIE static) replaces `prlimit → setpriv → bwrap` behind the same scope and mount plan (`chain(..., launcher=)`, `LauncherBackend`); `auto` takes it only when `launcher.verify()` passes (sha256 = `claude_hooks/sandbox/launcher_pin.json` for the arch, static ELF, owned by us, file and dir not group/other-writable), else bwrap. A source change must be re-pinned (`scripts/build_council_sandbox.py --pin`; `TestPin` fails otherwise); `step_sandbox` in `scripts/deploy.py` installs only the pinned build, `check_sandbox` runs `launcher.escape_smoke` through the live backend. The scratch / view owner is the backend's `sandbox_uid()`, never keyed on its name. In write mode the coder gets its own view (`GraphDeps.lane_workspace`, lane `coder:<n>`, `ShellToolProvider.workspace()`): `write_file` lands there chowned to that uid, `run_command` runs there, its loop gets 60 turns (12 without a view) with every tool but `write_file` stripped at 54 (6) (`LoopConfig.keep_after_strip`; other calls get `TOOLS_NARROWED_ANSWER`), and `LoopConfig.turn_check` = `nothing_written_check(12, every=12, …)` (4) from `claude_hooks/test_reruns.py` with `turn_check_repeat` nudges every 12 (4) turns while it has written nothing, sharper each time (council run 8). `parse_coder_tasks` splits a task naming more than `CODER_FINDINGS_PER_TASK` (2) finding ids into lanes (`split_coder_tasks`, at most `CODER_MAX_TASKS` (4) lanes in all; planner tasks naming none are kept as they are). A probe in `/scratch` whose relative import missed gets `import_hint()` on its result (`shell_provider.py`), naming the absolute path under the cwd; `CoderArtifact.workspace`/`commands` tell the synthesizer what ran. A researcher with `run_command` gets `researcher_iters()` (+max(10, iters//2); caps in `EFFORT_CAPS`: high 40/32, max 80/72).
