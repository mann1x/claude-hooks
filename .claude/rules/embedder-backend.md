- claude-hooks chooses the embedder's backend, never the engine (ch-33): `embedding.mode` is one of `llamafile_backend.BACKENDS` (`cpu` / `vulkan` / `cuda` / legacy `auto`). Every spawn passes its backend flags from `llamafile_backend.flags()`: `cpu` → `--gpu disable`, `vulkan` → `--gpu vulkan -dev <VulkanN> -ngl 99`, `cuda` → `--gpu nvidia -dev <CUDAn> -ngl 99` (needs a CUDA composite). An opencoti llamafile started without `--gpu` picks a GPU itself, so never spawn without one. `auto` keeps the pre-ch-33 flags only for configs that already say it.
- Runtime switch: `EmbeddingManager.switch()` / `reset()`, served as daemon RPC (`_embedding_backends` / `_embedding_switch` / `_embedding_reset`), as HTTP by `claude_hooks/embedder_http.py` on `embedding.control_host:control_port` (127.0.0.1:38091; POST from loopback only), and as `claude-hooks-daemon-ctl embedder status|backends|switch|reset`. A switch resolves the target before touching anything (409 when it is missing), restarts only when `_busy()` is false on two reads, and persists to `~/.claude/claude-hooks-embedder-backend.json` until `reset`. `_busy()` is an open client connection to the embed port (`open_connections()`) OR a slot processing OR `/slots` timing out: `/slots` alone reads idle for seconds after a request connects, and the first live switch cut one. Never reduce it to `/slots`.
- PCI addresses: `--list-devices` prints none (c14 r19). `with_pci()` fills CUDA from nvidia-smi — valid only because `child_env()` sets `CUDA_DEVICE_ORDER=PCI_BUS_ID`, so keep it — and Vulkan from sysfs by vendor, blank when ambiguous; `_confirm_pci()` takes the running device's from `/props`. `embedding.pci` wins over `device`. Tests never see the host GPU (`_no_host_gpu_probe` in `tests/conftest.py`) and never download a composite (`_no_composite_download`).
- `embedding.device` names the GPU by a `VulkanN` id or part of its name (`RENOIR`). `resolve_device()` resolves it before each spawn against `<llamafile> --gpu vulkan --list-devices` (`list_devices()` / `parse_devices()`). Empty means the only listed device; several devices with no name is refused.
- A Vulkan start is checked: `check_vectors()` compares three probe texts with the shipped CPU reference `claude_hooks/embedder_probe_reference.json`. Below `MIN_PROBE_COSINE` (0.99) the daemon falls back to CPU for the session and records `fallback_reason` (shown in status). On solidpc's Mesa 20.3.5 RADV the vectors came back wrong (cosine 0.38) with no error, so never skip the check for a driver that "works". `verify_backend` (default on) runs it only for the shipped model; `allow_old_driver` (`OPENCOTI_VK_ALLOW_OLD_DRIVER=1`) is only safe with the check on.
- `embedding.vulkan_icd` gives the child its own driver (`VK_ICD_FILENAMES`, child only). `scripts/build_private_radv.sh` builds RADV 25.2.8 (ACO only) plus libdrm into a prefix of its own for a host whose Mesa is too old. Never replace the system Mesa.
- The child gets a private `HOME` / `TMPDIR` under `~/.claude` (`runtime_dir()`, `child_env()`). Under the daemon's sandbox (`ProtectSystem=strict`) the engine otherwise cannot unpack its bundled Vulkan library and silently loads a stale one from `~/.llamafile`.
- The opencoti c14 r19 composites (CPU + Vulkan, 932 MB; CPU + Vulkan + CUDA per OS, ~1.9 GB each to stay under GitHub's 2 GiB asset limit; `.args` with no backend, checked by `oc_compose.sh`) are built from pinned inputs (`vendor/llamafile/opencoti-c14-r19/README.md`) and published as release `embedder-c14-r19`; their sha256 lines live in `vendor/llamafile/dist/SHA256SUMS.composite`, which the installer verifies:
  ```bash
  make -C vendor/llamafile/dist fetch-opencoti opencoti opencoti-cuda
  ```
- `install.py` asks for the composite (`_EMBEDDER_COMPOSITES`) and the backend, keeps an existing one, and a fresh install defaults to `cpu`. A new embedding knob goes into `install.py`, `config/claude-hooks.example.json` and `docs/llamafile-integration.md` in the same commit.
- Tests: `tests/test_llamafile_backend.py`, `tests/test_embedding_manager.py`, `tests/test_install_embedding_engine.py`. Runbook: `docs/llamafile-integration.md`.
