- One Markdown file per task under `<project>/.claude-hooks/tasks/` is the record. The `tasks` table on the host's store (pgvector or sqlite_vec) only indexes the files, for listing, cross-project views and recall. A host without a store still has working tasks: build the service with `service_for(provider=None)` from `claude_hooks/tasks/__init__.py`.
- `TaskService` (`claude_hooks/tasks/service.py`) writes the task file before the row. A failed index write is logged and repaired by the next `reconcile()`; never write the row first.
- One checkout indexes a project (ch-28, `docs/PLAN-task-graph.md` phase 0): `TaskService._writes_index()` is true only for a non-mirror that owns the `task_projects` row (`_claim()`: unregistered, same root, or a same-host root that is gone or is a worktree of this one; `adopt()` forces it and reconciles with `force=True`). A linked worktree (`checkout_of()` in `files.py`, from `.git` → `gitdir:` → `commondir`, never a `git` subprocess) is a mirror: `worker` on a branch edits its existing tasks in its own folder, `read-only` (detached, or a `hooks.tasks.read_only_worktrees` glob) reads the main checkout's folder (`svc.dir` is main's, `svc.origin` the worktree); both refuse create / done / cancel, never write the index, and a worktree without a folder starts no project. New ids sit above `index.max_number()` (`TaskDir.create(floor=)`). Never gate a write on `self.index is not None` alone — use `_writes_index()`. Agreed with the opencoti integrator (mail #2331 / #2332): main is the single source of `op-` ids. Tests: `tests/test_tasks_checkouts.py`.
- The cross-project task graph (ch-28 phase 1, `claude_hooks/tasks/graph.py`): `TaskService.graph()` builds a `Graph` from this project's rows (its files, or its own index rows) plus every other project's rows from `TaskIndex.edges()`; reading the index is open to any checkout, only writing is gated. A task writes only its own project's files: an edge into another project is stored on our side (`depends`, or a typed link in `TASK_LINK_KINDS` under `links`) and the reverse view (`Graph.reverse()`, `REVERSE_NAMES`, `TaskService.relations()`, the `## Graph` block of `task-show`) is computed, never written into the other project. The prefix is the global namespace (`op-347` from anywhere). Only `depends` blocks: `board()` takes `open_depends` from `Graph.open_depends()` (an id that cannot be resolved — unknown prefix, unknown task, unreachable or absent index — is blocking with its `Ref.reason` in `row["unresolved"]`, never done; `row_line` marks it `?`) and `blocking` from open dependents in every project. `_check_depends()` refuses an unknown prefix or task while the index answers, keeps it (logged) when it does not, and refuses a cycle across projects (`cycle_through()`, path in the message). `link()`: `parent` holds one id and refuses a loop; `duplicate-of` cancels this task, `supersedes` cancels the replaced one only when it is local (both closes refused in a mirror). Tests: `tests/test_tasks_graph.py`.
- Closing a task reports what it unblocks (ch-28 phase 2): `set_status()` to a closed status fills `last_unblocked` from `Graph.unblocked_by()` read before the close (nothing for a task already closed); `TaskTools._unblocked()` lists them and, for other projects with `hooks.tasks.unblock_mail` on, `notify.mail_unblocked()` mails `project_session()` — the live mailbox registration whose `cwd` is under the project's `task_projects` root on its host, newest `last_seen` — through the session's own `mailbox-send` (doorbell included), never to itself, never writing the other project. Both memory servers set `task_tools.mailer_fn = self._mailbox` in `_tasks()`; the CLI has no mailer and only lists. Tests: `tests/test_tasks_unblock.py`.
- Gates (ch-28 phase 3, `claude_hooks/tasks/gates.py`): open gates are strings in the task's `links["gates"]` (no schema change; older code keeps the key), normalised by `gates.parse()` (`mail:<id>`, `human:<what>`, `timer:<ISO>`, `commit:<sha>@<branch>`, `gh-pr:<owner/repo>#<n>`, `gh-run:<owner/repo>#<id>`). An open gate blocks in `board()` (`open_gates`) and keeps a dependent out of `Graph.unblocked_by()`. `TaskService.gate()` adds / resolves / removes one (logged); `check_gates()` runs `Checker` and records a resolved gate (removed + logged) or a stuck one (`Verdict.failed`, logged once), and only reports in a read-only checkout. `mail` resolves on an ack note or a later message from the recipient back to the sender naming `#<id>` (`MailboxStore.message_state()`, read-only); `commit` uses `git merge-base --is-ancestor`; `gh-*` call `gh` and run only on request (`cheap_only` at SessionStart: `hook._check_cheap_gates()`). Surfaces: the `task-gate` tool, `claude-hooks-tasks gate|gates` (the CLI checks mail gates through the host's mailbox store but sends no mail). Tests: `tests/test_tasks_gates.py`.
- Views, claims, defer (ch-28 phase 4): `graph.walk()` / `layers()` (a layer may be empty — the index is the layer number; an open dependency outside the drawn set keeps its dependent off layer 0) / `text_view()` / `mermaid()` back `task-graph` (`TaskTools._graph`, `view: blocked` → `_blocked`) and `claude-hooks-tasks graph|blocked`. `task-start` from a session with a mailbox identity goes through `TaskTools._claim()`: refused when `claimed_by` names another `alias@host` live in `store.sessions(alias=)` unless `force`; `TaskService.claim()` records it, closing clears it. The field is `claimed_by`, never `owner` (people write `owner:` by hand; it stays an extra). `defer` hides a task and its `parent` children in `board()["deferred"]` (active never). Both ride the index row as `_claimed_by` / `_defer` inside `links` (`store._links_for_row()`, popped by `_decode()`), never new columns — other hosts' older code writes the table with a fixed column list. Tests: `tests/test_tasks_views.py`.
- `reconcile()` lets the files win. Unchanged files are recognised by `(mtime_ns, size)` from `.index-state.json`, changed ones are re-read and upserted, and rows whose file is gone are deleted.
- Per-host state (`.index-state.json`, `.nudge-<sid>.json`, `.cc-<sid>.json`) lives in `~/.claude/claude-hooks-tasks/<project>-<hash>/` (`state_dir_for()` / `read_state()` / `write_state()` in `claude_hooks/tasks/files.py`), never in the task folder: the hook daemon (`ProtectSystem=strict`) can write only `~/.claude`. `read_state()` falls back to the old in-folder copy. `CLAUDE_HOOKS_TASKS_STATE_DIR` overrides the root, and `tests/conftest.py` isolates it per test.
- Layout (`claude_hooks/tasks/files.py`): `config.toml` holds `prefix` and `project`, open tasks are `<prefix>-<n>.md`, done and cancelled ones live in `archive/`. The prefix is derived once by `derive_prefix()` and written down, never re-derived, so renaming the directory doesn't renumber old references.
- `TaskDir.create()` allocates ids with an `O_EXCL` create, not a lock file. A number already used in `archive/` is skipped.
- File format (`claude_hooks/tasks/model.py`): front matter in a restricted YAML subset parsed with the stdlib (bare or double-quoted scalars, flow lists, flow maps), then `## Description` and `## Acceptance` (rewritten in place) and `## Log` (append-only, newest first). Sections a person adds are kept. A value the parser doesn't understand is kept as a string, never refused. Don't add a YAML dependency.
- Statuses are `pending` / `active` / `waiting` (open) and `done` / `cancelled` (closed); priorities are `H` / `M` / `L`.
- `TaskIndex` (`claude_hooks/tasks/store.py`) borrows the provider's connection and its lock, the same rule as `claude_hooks/mailbox/store.py`. It never opens a second connection, and every failure path rolls back.
- `claude_hooks/tasks/schema.py` serves both dialects with one set of queries: times are ISO-8601 UTC text, list and map fields are JSON text. The embedding is a base64 float32 blob in a TEXT column, not `vector(n)`, and similarity is computed in Python. `embed_model` tags each vector, and rows from another model are re-embedded (`embed_pending()`), never compared across spaces.
- `service_for(..., embed=False)` keeps the write path free of embedder round-trips; `embed_pending()` catches up later.
- `tool_catalog()` and `TaskTools` in `claude_hooks/tasks/tools.py` are the 13 `task-*` MCP tools (`task-create`, `-ready`, `-list`, `-show`, `-start`, `-done`, `-wait`, `-cancel`, `-note`, `-update`, `-link`, `-graph`, `-gate`), served by both `claude_hooks/pgvector_mcp/server.py` and `claude_hooks/sqlite_vec_mcp/server.py` through `tools_for_provider()`. A tool added to one server goes on the other too.
- `claude_hooks/tasks/cli.py` is the `claude-hooks-tasks` CLI (`bin/claude-hooks-tasks`, `bin/claude-hooks-tasks.cmd`). It works from the directory you are in, so its Windows shim does not `cd` into the repo.
- `write_board()` in `claude_hooks/tasks/board.py` regenerates `<project>/TASKS.md` on every change; `claude_hooks/tasks/render.py` holds the shared row and board text.
- Hooks live in `claude_hooks/tasks/hook.py`, each with a switch under `hooks.tasks` in `config/claude-hooks.json`: `session_block()` (SessionStart, `session_start` / `session_ready`), `prompt_block()` and `PromptRecall` (UserPromptSubmit, `prompt_mentions` / `prompt_recall` / `recall_k` / `recall_min_score`), `stop_nudge()` (Stop, once per change, never on a continuation) and `mirror_builtin()` (PostToolUse, `mirror_builtin`); `unblock_mail` (default on in `config/claude-hooks.example.json`) gates the cross-project unblock mail. `hooks.tasks.enabled: false` turns off the hooks and the MCP tools (`tasks_enabled()`).
- The mirror needs the PostToolUse matcher to include `TaskCreate|TaskUpdate`. `install.py` writes it and `scripts/deploy.py` reconciles an older one.
- In a project with a `.claude-hooks-disable` marker the task hooks run only with `keep: tasks`, routed through `claude_hooks/hook_parts.py`. That is a second path: test it in `tests/test_tasks_hooks.py`.
- `claude_hooks/tasks/importer.py` replays `TaskCreate` / `TaskUpdate` calls from a transcript (`claude-hooks-tasks import --transcript <session.jsonl> [--dry-run]`). Ids keep their number with the prefix, replaced descriptions are kept under `## Earlier descriptions`, and a re-run skips ids that already have a file.
- Tests: `tests/test_tasks.py` (format, folder, index), `tests/test_tasks_tools.py` (tools, CLI, board, importer), `tests/test_tasks_hooks.py` (hooks and the marker route), `tests/test_tasks_checkouts.py` (one indexing checkout, worktree mirrors), `tests/test_tasks_graph.py` (cross-project graph), `tests/test_tasks_unblock.py` (unblock report and mail), `tests/test_tasks_gates.py` (gates). Reference: `docs/tasks.md`. Plans: `docs/PLAN-task-tracking.md`, `docs/PLAN-task-graph.md`.
