---
description: Secret gate on every commit — gitleaks with .gitleaks.toml plus a search for this host's own secrets, failing closed
---

- Every commit passes the secret gate: `.git/hooks/pre-commit` runs `scripts/secret_scan.py --staged` first, failing closed. It runs gitleaks with `.gitleaks.toml` (the default rules plus `url-credentials`, `config-secret-value` and the path-only `local-config-or-key-file`), then searches every added line for this host's own secrets — any 12-character run of a value from the configs' DSNs and secret-named keys, every `key_file`, `~/.claude/*api-key*`, `~/.claude/*.key`, `~/*.key` and secret-named environment variables (`known_secrets()`). A finding names the file, the line and where the secret lives, never the value. Reference: `docs/secret-scan.md`.
- Why: c2f2caa (2026-05-07) pushed `config/claude-hooks.json.bak-*` with the pgvector DSN password to the public repo. No gate ran, and gitleaks' stock rules scan that commit clean, because none reads a password inside `scheme://user:password@host`.
- A refused commit means removing the secret from the commit. Never add a finding to `.gitleaksignore` or an allowlist to get a commit through; `.gitleaksignore` holds only findings already in public history, accepted by the owner. Never commit a copy or backup of `config/claude-hooks.json`, `consultants.toml` or `consultants-config.toml`: the `*.example.*` files are the shareable templates.
- `claude-consultants config set-* --project` writes the merged config into `<project>/.claude-hooks/consultants.toml`; `save_config()` turns every line whose value carries a credential (a URL with a password, a secret-named key) and equals the user-global value into an `inherited` comment (`_drop_inherited_secrets()` in `consultants/config.py`) — the merge at load still supplies it, and an endpoint without an `api_key` line keeps the key of the same-URL endpoint below it. It used to copy the pgvector DSN with its password into every project tree. Test: `test_a_project_file_never_copies_an_inherited_credential`.
- A test that needs a secret-shaped value generates it at runtime (`secrets.token_urlsafe`) or uses a fake carrying `test-only` / `not-a-real`; never a real value or a prefix of one (781ea3a used 32 of the password's 40 characters as a fixture). Split literal key headers (`"-----BEGIN " + "PRIVATE KEY-----"`).
- Anything that writes `.git/hooks/pre-commit` merges a marked block and keeps every other line; never `cp`/`cat >` over the hook. `scripts/install-caliber-hook.sh` replaces only its `# caliber:pre-commit[:vN]:start`..`end` span (caliber's own block included) or appends after the gate, refuses an unmatched marker, and warns on an earlier top-level `exit` or a gate below the block; it used to `cp` over the hook and delete the gate (backup_models #1940). Tests: `tests/test_install_caliber_hook.py`.
- `.git/hooks` is not tracked: `step_repo` in `scripts/deploy.py` installs the gate (`secret_scan.install_hook()`, which replaces an older block in place), and `check_secret_gate` in `scripts/verify_deploy.py` FAILs when the hook is missing or gitleaks is not installed. `.github/workflows/secret-scan.yml` scans every commit on push with a checksum-pinned gitleaks, so a `--no-verify` commit is still caught. Tests: `tests/test_secret_scan.py` (each rule's own canaries, placeholders that must pass, the history scan), `TestSecretGate` in `tests/test_deploy_completeness.py`.
