# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** `claude-hooks-daemon-ctl` does NOT have a `ping` subcommand — valid choices are `{status, start, stop, restart, tail}`. Use `daemon-ctl status` to verify liveness; `daemon: responding on 127.0.0.1:<port>` in the output means alive. Also: the daemon's autostart unit on solidpc is `/etc/systemd/system/claude-hooks-daemon.service` (system, NOT `--user`) — `systemctl --user restart claude-hooks-daemon` returns `Unit ... not found`; use `daemon-ctl restart` which dispatches via the platform manager correctly.
- **[pattern]** After editing `config/claude-hooks.json` (e.g. flipping a HyDE model), the daemon caches the config — bounce it with `bin/claude-hooks-daemon-ctl restart` before the new value takes effect on the next hook call. Always manual-backup first: `cp config/claude-hooks.json config/claude-hooks.json.bak-<purpose>-$(date +%Y%m%d-%H%M%S)` (see existing `feedback_install_destructive_noninteractive` memory).
- **[convention]** A behavior change baked as the default for `install.py` requires updating ALL THREE surfaces in one commit: (1) `install.py` `_setup_ollama_chat` (or the analogous setup fn) `proposed_*` default expression, (2) `config/claude-hooks.example.json`, (3) `docs/<feature>.md` defaults table. Drift between the three is a high-risk silent-divergence trap that future re-runs of the installer surface only when a user notices a stale value.
- **[pattern]** Per-role consultants config mutations are done via `claude-consultants config set-role <role> --model <tag> [--enabled true|false]` (NOT by hand-editing `~/.claude/consultants-config.toml`). Mirror to pandorum over native Windows SSH using the conda env's full path: `ssh pandorum 'C:\Users\manni\miniconda3\envs\claude-hooks-consultants\Scripts\claude-consultants.exe config set-role …'`. Always back up first: `cp ~/.claude/consultants-config.toml ~/.claude/consultants-config.toml.bak-<purpose>-$(date +%Y%m%d-%H%M%S)`.
- **[gotcha]** The pgvector provider's table name is NOT stored on the instance as `self._table` — it is re-derived inline at every call site as `_safe_table(self.options.get("table") or "claude_hooks_memory")`. Read it from `pg["table"]` in the JSON config, not from a provider attribute. Similarly `ServerCandidate` (in `claude_hooks/providers/base.py`) uses fields `server_key`, `url`, `headers`, `source`, `confidence`, `notes` — NOT `name`/`source_kind`/`config`/`raw`. Use `make_embedder(name, options)` to build an embedder (NOT `embedder_for`).
- **[pattern]** Live llamafile embedder smoke uses `make_embedder("llamafile", opts)` from `claude_hooks.embedders` against the URL/model/num_ctx in `config/claude-hooks.json -> providers.pgvector.embedder_options`. Hash the first-16 dims (`hashlib.md5(",".join(f"{v:.5f}" for v in vec[:16]).encode()).hexdigest()[:12]`) as a drift sentinel — solidpc baseline is `7925bb1e13d4` for the probe `"claude-hooks llamafile embedder smoke 2026-05-19"` with `qwen3-embedding:0.6b` at ctx 16384. Identical checksum across hosts proves byte-identical model weights independent of perf.
- **[gotcha]** After restarting the daemon, `curl http://<host>:<port>/embedding` from a fresh shell returns `Connection refused` even though the daemon is up — the llamafile child is **spawn-on-demand**, not eager. Trigger the spawn before testing the listener with `python -c 'from claude_hooks.daemon_client import embedding_ensure; print(embedding_ensure())'` (must return `{'ready': True, 'spawned': True}`), then probe the port. Available daemon RPCs are exactly `embedding_ensure / embedding_status / embedding_shutdown` (no other names).
- **[gotcha]** Setting `embedder_options.daemon_ensure = false` on a host stops THAT host's daemon from spawning a local llamafile on embed calls, but does NOT terminate any already-running supervised llamafile child. After flipping the flag, a daemon restart is required — and on Windows the supervised child may *survive* the restart as an orphan listening on the configured port. Verify with `Get-NetTCPConnection -LocalPort <port> -State Listen` and kill via `Stop-Process -Id $p -Force` if needed. Mutate the canonical consultants TOML via `from consultants import config as cc; cfg = cc.load_config(); ...; cc.save_config(cfg, scope="user")` — never hand-edit `~/.claude/consultants-config.toml`.
- **[gotcha]** `ssh pandorum '... python -c "from claude_hooks ..."'` fails with `ModuleNotFoundError: No module named 'claude_hooks'` when run from `%USERPROFILE%` — `claude_hooks` is not pip-installed in pandorum's conda env, it is imported by path. Either `cd %USERPROFILE%\claude-hooks` first (`ssh pandorum 'cd %USERPROFILE%\claude-hooks && python -c ...'`) or `sys.path.insert(0, str(Path.home() / "claude-hooks"))` in the script. The `Scripts/claude-hooks-daemon-ctl.cmd` wrappers handle this transparently, raw `python -c` does not.
- **[gotcha]** `Get-Process -Id <pid> { $_ }` on the default Windows PowerShell fails with `Cannot process command because of one or more missing mandatory parameters: IncludeUserName.` Don't pipe-then-`Get-Process` with a script-block argument; capture the PID into a variable first: `$p = (Get-NetTCPConnection -LocalPort <port> -State Listen).OwningProcess; Get-Process -Id $p`. Also, `netstat -ano | findstr` over ssh requires escaping the pipe — easier to use `powershell -NoProfile -Command "..."` end-to-end.

For programmatic mutation from Python, use the canonical API: `from consultants import config as cc; cfg = cc.load_config(); cfg.<field> = ...; cc.save_config(cfg, scope="user")`. Always back up first: `cp ~/.claude/consultants-config.toml ~/.claude/consultants-config.toml.bak-<purpose>-$(date +%Y%m%d-%H%M%S)`.

Read it from `pg["table"]` in the JSON config, not from a provider attribute. - **[pattern]** Cross-host config mutation on Windows pandorum: write a small Python script locally to `/tmp/<name>.py`, `scp /tmp/<name>.py pandorum:<name>.py`, run with `ssh pandorum '<conda-env-python.exe> %USERPROFILE%\<name>.py'`, then `ssh pandorum 'del %USERPROFILE%\<name>.py'`. Avoids PowerShell quote-escaping. For `claude-hooks.json` use `pathlib.Path(Path.home() / "claude-hooks" / "config" / "claude-hooks.json")` + `json.dumps(..., indent=2)`; for `consultants-config.toml` use the `consultants.config` API.
- **[gotcha]** Caliber's pre-commit hook runs `caliber refresh` in the background after every commit (visible as `caliber: refreshing docs in background...`). The refresh may modify `CALIBER_LEARNINGS.md` and other agent-config files — those changes appear in the next `git status` as fresh diff. Expect to follow each substantive commit with a `docs(caliber): refresh ...` commit if the curator's output changed anything material.
- **[convention]** LAN-shared llamafile embedder topology: producer host sets `embedding.host = "0.0.0.0"` in `config/claude-hooks.json` (overriding the loopback-only `EmbeddingConfig` default) and restarts the daemon to bind LAN-wide. Consumer hosts set `providers.pgvector.embedder_options.url` to `http://<producer-ip>:38092/embedding` AND `daemon_ensure = false` in BOTH `providers.pgvector.embedder_options` AND `[store.embedder_options]` (consultants TOML) so the consumer's daemon doesn't spawn a redundant local llamafile. Same model + same weights = byte-identical vectors across hosts (verify with the 16-dim checksum sentinel).
- **[correction]** Test fixtures must NOT bake in real-infrastructure identifiers (LAN IPs like `192.168.x.x`, host-specific table names like `memories_qwen3`, real DSNs, real LAN URLs). Use **RFC 5737 documentation ranges** for IPs (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`), generic table names (`memory`, `claude_hooks_memory`), and example DSNs (`postgresql://user@127.0.0.1/db`). User correction 2026-05-21: "if someone else downloads claude-hooks and wants to run the same tests, it doesn't fail. Otherwise no one will be able to develop improvements and open an upstream PR if needed." If real-infra values are genuinely required for some local-only test, ship a gitignored template-override file so external contributors aren't blocked.
- **[gotcha]** When `_setup_*` installer functions gain a new `input()` prompt, EVERY scripted-input fixture across `tests/test_install_*.py` needs a corresponding `""` (or explicit) answer at the right position in the `_scripted_input([...])` list — otherwise the test fails with `AssertionError: dialog asked an unscripted question: <prompt>`. The dialog order is positional; a new mid-dialog prompt shifts all subsequent answers. After adding any new prompt, grep for every call site that scripts the affected setup function and pad each list.
- **[pattern]** Pushing/pulling git on pandorum from solidpc: use `ssh pandorum 'cmd /c "cd /d C:\Users\manni\claude-hooks && <git-cmd>"'`. The Bash-style `/c/Users/manni/...` path that works under WSL fails silently on pandorum's OpenSSH server (returns empty stdout, no error). Repo path is `C:\Users\manni\claude-hooks` — do not fish around for it.
- **[convention]** install.py embedder validators (`_validate_pgvector_only`, `_validate_sqlite_vec_only`) must inspect `embedder_options.daemon_ensure` to distinguish local (daemon-managed, `True`) from remote LAN-shared (`False`) llamafile mode. Label them differently (`(daemon-managed)` vs `(remote, no local supervision)`), and suppress the "daemon spawns llamafile on demand" hint in remote mode — that note is wrong when this host isn't the spawning host. A single hard-coded `daemon-managed` label silently misleads consumers of a LAN-shared embedder.
- **[pattern]** When adding a new branch to `_setup_embedding_engine` or `_setup_llamafile_engine` (e.g., "remote llamafile?" prompt, "expose on LAN?" prompt), the dialog-state changes need to be mirrored in THREE places in the same commit: (1) the installer fn itself, (2) `config/claude-hooks.example.json` (new example block or comment), (3) `docs/llamafile-integration.md` (topology section). Drift between the three is a high-risk silent-divergence trap.
- **[pattern]** Centralize fixture network identifiers in `tests/_fixtures_net.py`. Defaults draw from RFC 5737 documentation blocks (so they're obviously fake); each constant is overridable two ways — process env `CLAUDE_HOOKS_TEST_*` vars (CI-friendly), and a gitignored `tests/.env.local` file (developer-friendly, parsed `KEY=value`, process env wins on conflict). New tests `from tests._fixtures_net import FIXTURE_LAN_HOST, FIXTURE_PG_DSN, FIXTURE_OLLAMA_PROXY_GENERATE, FIXTURE_PROXY_URL, FIXTURE_EPISODIC_URL, ...` — never inline a host/URL/DSN literal. See `tests/README.md` for the contribution guide.
- **[convention]** `tests/_fixtures_net.py` is the canonical home for all network-shaped test constants (`FIXTURE_LAN_HOST`, `FIXTURE_LAN_HOST_ALT`, `FIXTURE_PROXY_URL`, `FIXTURE_EPISODIC_URL`, `FIXTURE_OLLAMA_PROXY_BASE`, `FIXTURE_OLLAMA_DIRECT_EMBEDDINGS`, `FIXTURE_LLAMAFILE_URL`, `FIXTURE_PG_DSN`, `FIXTURE_PG_DSN_ALT_PORT`, `FIXTURE_REGEX_IP_PRIMARY`, `FIXTURE_REGEX_IP_SECONDARY`). Defaults are RFC 5737 documentation ranges so the suite is portable for any external contributor; values can be overridden locally via `CLAUDE_HOOKS_TEST_*` env vars or `tests/.env.local`. Import these — never inline `192.168.x.x` / `10.0.0.x` / real DSNs in a new test.
- **[pattern]** Before committing a test change that touches networking, regex IP matching, DSNs or URLs, run `grep -rn -E '192\.168\.[0-9]+\.|10\.0\.0\.[0-9]+' tests/ --include='*.py'` — output must be empty. The one legitimate exception is regex test fodder (assertions that the IP-parsing code rejects/accepts a literal); use `FIXTURE_REGEX_IP_PRIMARY` / `FIXTURE_REGEX_IP_SECONDARY` for that purpose with a comment explaining the intent isn't infra.
- **[pattern]** Integration tests that historically defaulted to a real host (e.g. `test_pgvector_integration.py`'s `OLLAMA_EMBEDDINGS_URL` / `PGVECTOR_DSN`) keep the existing env-var override for backward compatibility, but fall through to a `FIXTURE_*` documentation default. A contributor without local infra then either sees a clean skip or a `Connection refused` they understand — never a silent pass against the maintainer's LAN.
- **[gotcha]** When refactoring test files to consume `_fixtures_net`, write the import block as `from tests._fixtures_net import FIXTURE_X` (the test root is added to `sys.path` by the runner / by an explicit `sys.path.insert` in some files). Don't use a relative `from ._fixtures_net import …` — most existing tests in this suite are not run as a package and the relative form breaks them.
- **[pattern]** When switching branches with an in-progress Caliber-generated `CALIBER_LEARNINGS.md` diff that conflicts with the target branch, the cleanest recovery is `git checkout --theirs CALIBER_LEARNINGS.md && git stash drop` (after a failed stash-push/pop cycle). The file is fully regenerated by `caliber refresh` so taking the target branch's version loses nothing — Caliber will re-emit the local additions on the next commit. Don't `git stash` it first; it just creates a conflict you then have to resolve anyway.
- **[pattern]** When wiring a new in-process subsystem into the hooks, mirror the existing opt-in subsystem shape: a single `hooks.<name>` block in `claude_hooks/config.py:DEFAULT_CONFIG` with `enabled: False` as the master toggle, plus per-knob sub-flags (timeouts, paths, blacklists). The installer (`install.py`) flips `enabled` to `True` on user confirmation — the default never auto-enables. Mirror neighbor blocks (`code_graph`, `companions`, `post_tool_use`) for the comment style and field ordering. Smoke-test with `python -c "from claude_hooks.config import DEFAULT_CONFIG; import json; print(json.dumps(DEFAULT_CONFIG['hooks']['<name>'], indent=2))"` before claiming the change works.
- **[convention]** `claude_hooks/lsp_engine/__init__.py` is the public re-export surface for the LSP engine — `LspEngineClient`, `connect_or_spawn`, `socket_path_for`, `Diagnostic`, `Engine`, `EngineConfig`, `load_cclsp_config`, etc. Consumers (hook handlers, integration helpers) should import from `claude_hooks.lsp_engine` (the package), NOT from `claude_hooks.lsp_engine.client` / `.daemon` / `.config` directly — the internal module layout is not the public contract.
- **[gotcha]** Pytest assertions on `input()` prompts must check the prompt-arg, not stdout. When a `_setup_*` dialog asks `input("[V/r/s]: ")`, the bracketed prompt string is the *argument* to `input()`, not stdout content — `assert "[V]alidate only" in capsys.readouterr().out` fails. Capture prompts by monkeypatching `builtins.input` to append `prompt` to a list, then assert against the list. Stdout-only `print()` lines (e.g. `validate-only complete`) remain checkable via `capsys`.
- **[pattern]** install.py setup functions wired into `main()` should be guarded by a structural regression test that greps install.py source order — e.g. `i_a = src.find("_setup_a(\n        cfg,")` / `i_b = src.find("_setup_b(\n        cfg,")` / `assert i_a < i_b`. Cheap to maintain, catches accidental reordering that would (e.g.) write the LSP-engine knob AFTER `save_config(cfg, cfg_path)` and silently drop it.
