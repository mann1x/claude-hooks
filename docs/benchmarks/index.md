This directory contains per-label benchmark runs of the canonical
queries documented in [`../consultants-benchmarks.md`](../consultants-benchmarks.md).

Each subdirectory is one label — typically a model tag plus a date
suffix when the same model is re-run after engine changes. Inside
each label, you'll find:

| File | What |
|---|---|
| `results.md` | Wall + status table; auto-generated by the runner |
| `<query>.summary.md` | The synthesizer's answer (verbatim) |
| `<query>.transcript.md` | Full role transcript |
| `<query>.waterfall.txt` | Per-role wall-time waterfall |
| `<query>.trace.jsonl` | Raw JSONL trace events |
| `<query>.metadata.json` | Token totals + retry counts |
| `<query>.status` | Wall, sid, status (machine-readable) |

## How to add a sweep

```bash
scripts/consultants_benchmark.sh <label> --model <ollama-tag>
```

Examples:

```bash
# Pin every role to a specific model
scripts/consultants_benchmark.sh kimi-k2.6-cloud-2026-05-07  # default config

scripts/consultants_benchmark.sh deepseek-v4-pro-2026-05-XX --model deepseek-v4-pro:cloud

scripts/consultants_benchmark.sh qwen3.5-cloud-2026-05-XX  --model qwen3.5:cloud
```

The label is yours to pick — convention is `<model-slug>-<date>`. If
you're A/B-testing engine config rather than models, use a
config-name suffix:

```bash
scripts/consultants_benchmark.sh kimi-k2.6-cloud-no-fanout-2026-05-07  # FANOUT_MAX_LANES=1
```

- **Audit-medium-style retrieval** at deeper coverage → `kimi-k2.6:cloud` or `gemma4:31b-cloud` (both single-run-only, but their A on retrieval was rich).

### Observations

- **U-curve between size and Q2 quality.** Mid-tier models (gemini, deepseek-v4-flash, nemotron-3-super) get verdicts right; the smallest (nemotron-3-nano, qwen3-coder-next) miss ground-truth sites in places they didn't search; the largest (mistral-large-3, deepseek-v4-pro) over-think and mis-classify protected-site reasoning. Bigger ≠ better on grep-style audits.
- **Three valid hardening recommendations on Q3.** The strong-Q3 answers each propose a fix at a different layer: nemotron-3-super wraps `_wrap_researcher` in `graph.py`; qwen3-coder-next changes `researcher_node` to re-raise; deepseek-v4-pro flips status logic in `runner.py`. All three diagnoses are correct; the disagreement is which layer should own the fix. Useful artifact for any future hardening PR.
- **`deepseek-v4-pro:cloud` is no longer broken** on the local proxy as of 2026-05-09 — the previous block (memory entry from 2026-05-06) has cleared. Memory updated.
- **`mistral-large-3:675b-cloud` fabricated** `return_exceptions=True` on `compiled.stream` — that parameter does not exist on LangGraph's `.stream()`. Disqualifying for any role that produces user-facing recommendations.
